AUTHORIZATION PROBLEM

ACCESS WITHOUT CHAOS.

THE PROBLEM

DIRECT PERMISSIONS DON'T SCALE.

Assigning permissions directly to individual users creates administrative overhead and makes access difficult to understand and maintain.

THE MODEL

SEPARATE IDENTITY FROM ACCESS.

AGDLP introduces structured group layers between users and protected resources, creating a repeatable authorization model.

AUTHORIZATION MODEL

ACCOUNT → GLOBAL → DOMAIN LOCAL → PERMISSION.

ACCOUNT → GLOBAL GROUP → DOMAIN LOCAL GROUP → RESOURCE PERMISSION
01 / THE FOUR LAYERS

BUILD THE CHAIN.

A

ACCOUNTS

User identities represent the people or service identities that require access.

G

GLOBAL GROUPS

Global groups represent role or business membership and collect users with similar responsibilities.

DL

DOMAIN LOCAL GROUPS

Domain Local groups represent access to specific resources or permission scopes.

P

PERMISSIONS

Permissions are assigned to the resource through the appropriate authorization group.

02 / AUTHORIZATION ARCHITECTURE

IDENTITY → AUTHORIZATION.

ENTERPRISE ACCESS MODEL

USERS SHOULD NOT NEED TO KNOW PERMISSIONS.

Users are associated with business roles, while resource access is represented by authorization groups.

  • User accounts represent identity
  • Global groups represent roles
  • Domain Local groups represent resources
  • Permissions are assigned to resources
  • Access is inherited through group membership

03 / ROLE ENGINEERING

ACCESS FOLLOWS ROLE.

IDENTITY

USER ACCOUNT

The account identifies the individual requesting access.

BUSINESS

ROLE

The user's business function determines the appropriate role membership.

AUTHORIZATION

ACCESS GROUP

The authorization layer determines which protected resources can be accessed.

RESOURCE

PERMISSION

The resource receives permissions through the designated authorization group.

04 / SECURITY CONTROL

LEAST PRIVILEGE.

CONTROL

GRANT ONLY WHAT IS REQUIRED.

Authorization should reflect the user's actual business requirements rather than providing broad access by default.

GOVERNANCE

CHANGE THE ROLE, NOT EVERY ACL.

Group-based authorization reduces the operational effort required when users change departments or responsibilities.

05 / VALIDATION

PROVE THE ACCESS.

01

EXPECTED ACCESS

Verify that authorized users can reach the resources required by their role.

02

DENIED ACCESS

Verify that users outside the authorization path cannot access protected resources.

03

GROUP MEMBERSHIP

Validate that group membership correctly determines effective access.

04

PERMISSION REVIEW

Review resource permissions and ensure access follows the intended authorization model.

IAM GOVERNANCE

DESIGN FOR CHANGE.

JOINER

NEW USER

Assign the appropriate business-role membership instead of manually configuring resource permissions.

MOVER

NEW ROLE

Update role membership while keeping resource authorization centralized.

LEAVER

REMOVE ACCESS

Removing the identity from the authorization path should remove its effective access.
